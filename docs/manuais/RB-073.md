## 4. Passo a passo da tarefa

1. Levante consumo medido de IA, infraestrutura e serviços usados pelo MVP.
2. Consulte tarifas oficiais na data e registre unidade, moeda, fonte e hipóteses; não reutilize preço antigo sem verificar.
3. Monte três volumes com fórmulas explícitas e separe custo medido de estimativa.
4. Inclua sensibilidade a tokens, frequência, armazenamento e tráfego relevantes.
5. Compare qualidade/custo dos provedores e documente despesas ainda não conhecidas, sem tratar projeção como faturamento real.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c docs/rb-073-calcular-custos-e-viabilidade-economica
```

Se essa branch já existe, use `git switch docs/rb-073-calcular-custos-e-viabilidade-economica` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-073.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-073.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-073.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-073.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell

git commit -m "RB-073: Calcular custos e viabilidade econômica"
```

## 8. Quando pedir review e quando concluir

Peça revisão e mova para **Review** quando o PR tiver escopo conferível, documentação e validação anexadas. Resolva os comentários na mesma branch e repita os checks afetados. O autor não aprova o próprio PR. **Done** exige revisão, merge e validação do resultado integrado conforme o card/DoD; abrir PR ou publicar este manual não basta.
