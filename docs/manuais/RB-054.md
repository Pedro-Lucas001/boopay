## 4. Passo a passo da tarefa

1. Compare guia Google 2026-04-08, schema aberto datado e capacidades da superfície; registre divergências de estados antes de adotar enums.
2. Fixe tag/SHA, schemas por operação/direção, transporte, resolvedor/SDK e versão própria do payment handler.
3. Publique /.well-known/ucp apenas com capacidades implementadas, URLs e chaves públicas; proteja fetch de perfis contra SSRF.
4. Traduza criar/consultar/atualizar/concluir/cancelar ao core; distinga HTTP, ucp.status e estado da sessão.
5. Valide entradas/saídas e erros, repetição e isolamento; devolva pedido sem credential/signals e documente ciclo de eventos.
6. Registre resultado da suíte compatível, casos próprios e limites de sandbox/ativação Google.

Fontes técnicas para consultar na revisão escolhida: [Google: visão geral e caminhos](https://developers.google.com/merchant/ucp/guides/overview), [Google: API 2026-04-08](https://developers.google.com/merchant/ucp/implementation/2026-04-08/native-checkout-api), [Schemas UCP datados](https://github.com/Universal-Commerce-Protocol/ucp/tree/v2026-04-08/source), [Suíte de conformidade](https://github.com/Universal-Commerce-Protocol/conformance), [Google: ciclo de pedidos](https://developers.google.com/merchant/ucp/guides/overview/order-lifecycle). Reconfira versão e disponibilidade na data da implementação.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | HTTP 200 com ucp.status error não vira compra bem-sucedida. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Cotação alterada, conclusão concorrente, perfil malicioso e loja errada são tratados sem efeitos indevidos. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check
git diff --check
```

Acrescente teste comportamental pertinente em `tests/*.test.ts`, incluído pelo runner atual, quando houver código novo. Configure apenas ambientes descartáveis/autorizados para banco, loja e PSP; fixtures não comprovam integração externa.

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c feat/rb-054-implementar-adaptador-ucp-sobre-checkout-core
```

Se essa branch já existe, use `git switch feat/rb-054-implementar-adaptador-ucp-sobre-checkout-core` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-054.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-054.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-054.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-054.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-054: Implementar adaptador UCP sobre Checkout Core"
git push -u origin feat/rb-054-implementar-adaptador-ucp-sobre-checkout-core
```

Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head feat/rb-054-implementar-adaptador-ucp-sobre-checkout-core --web` após o push.
