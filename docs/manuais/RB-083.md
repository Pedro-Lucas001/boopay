## 4. Passo a passo da tarefa

1. Defina modelo canônico de cliente, IDs verificados, origem/propriedade de atributos e regra de conflito.
2. Integre vitrine, conversa e pedidos ao perfil por eventos idempotentes com linhagem.
3. Vincule sessão anônima e dispositivos somente mediante prova autorizada, com trilha de vínculo/desvínculo.
4. Propague finalidade, revogação, exclusão e retenção às projeções; não una pessoas por nome ou probabilidade.
5. Teste colisões, dois dispositivos, eventos atrasados, conflitos e isolamento entre lojas.
6. Integre consulta ao perfil 360 e demonstre atualização/exclusão de ponta a ponta.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Mesmo ID em lojas diferentes não mistura clientes. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Vínculo sem prova é negado; reprocessamento não restaura dado excluído indevidamente. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check
git diff --check
```

Acrescente teste comportamental pertinente em `tests/*.test.ts`, incluído pelo runner atual, quando houver código novo. Configure apenas ambientes descartáveis/autorizados para banco, loja e PSP; fixtures não comprovam integração externa.

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 6. Critérios de conclusão da issue

Critérios preservados do card consultado, com a referência documental atualizada para manual. Marcações existentes são registros anteriores; só acrescente validação que realmente executou.

- [ ] Registrar no manual o modelo canônico de cliente, identificadores, fontes, propriedade dos campos e regras de atualização/conflito.
- [ ] Unificar eventos e atributos de vitrine, chat e pedidos em perfil persistente, com origem/linhagem e atualização idempotente.
- [ ] Vincular sessão anônima a cliente autenticado e permitir continuidade entre dispositivos somente com prova de identidade autorizada; não usar inferência probabilística para juntar pessoas.
- [ ] Implementar regras determinísticas de resolução de identidade e trilha auditável de vinculação/desvinculação, sem unir clientes por nome ou dado não verificado.
- [ ] Respeitar consentimento, finalidade e retenção; propagar revogação/exclusão às projeções e documentar os limites legais de retenção de pedidos.
- [ ] Garantir isolamento por loja/tenant, inclusive quando duas lojas tenham identificadores de cliente iguais; compartilhamento entre lojas exige política explícita e autorização.
- [ ] Integrar consulta de perfil/linha do tempo ao perfil 360, com controle de acesso e atualização observável.
- [ ] Testar colisões de identidade, dois dispositivos, reprocessamento, conflito de atributos, revogação/exclusão e tentativa de acesso entre lojas; anexar evidências de uma jornada integrada.

Além deles, aplique a [Definition of Done](../definition-of-done.md). Não altere o escopo para esconder pendência.

Se essa branch já existe, use `git switch feat/rb-083-implementar-cdp-completo-e-identidade-avancada` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

