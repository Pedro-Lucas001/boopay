## 4. Passo a passo da tarefa

1. Liste Merchant, Integration, CatalogItem, CatalogReceipt e StoreEvent existentes, com PK, FK e índices.
2. Desenhe o vínculo loja → integração → produto/evento e explique a origem do tenant autorizado.
3. Defina identidade por integração + ID de origem; destaque a tabela Product legada e o risco do SKU global.
4. Documente revisão monotônica, tombstone de exclusão, recibos de deduplicação e timestamps.
5. Revise o diagrama com quem implementa RB-007/RB-016 e registre as decisões no dicionário.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Dois lojistas com o mesmo SKU permanecem separados no diagrama e nas chaves. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Evento antigo após exclusão não deve restaurar o produto segundo a regra documentada. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check:docs
git diff --check
```

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c docs/rb-006-modelar-lojas-integracoes-catalogo-e-eventos
```

Se essa branch já existe, use `git switch docs/rb-006-modelar-lojas-integracoes-catalogo-e-eventos` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-006.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-006.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-006.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-006.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-006: Modelar lojas, integrações, catálogo e eventos"
git push -u origin docs/rb-006-modelar-lojas-integracoes-catalogo-e-eventos
```

No GitHub, abra **Pull requests → New pull request**, base `main`, compare `docs/rb-006-modelar-lojas-integracoes-catalogo-e-eventos`. Use o [modelo de PR](../../.github/PULL_REQUEST_TEMPLATE.md). Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head docs/rb-006-modelar-lojas-integracoes-catalogo-e-eventos --web` após o push.

## 8. Quando pedir review e quando concluir

Peça revisão e mova para **Review** quando o PR tiver escopo conferível, documentação e validação anexadas. Resolva os comentários na mesma branch e repita os checks afetados. O autor não aprova o próprio PR. **Done** exige revisão, merge e validação do resultado integrado conforme o card/DoD; abrir PR ou publicar este manual não basta.

Se houver bloqueio, registre: passo que falhou, erro sanitizado, tentativa feita, dependência e ajuda necessária. Não simule sucesso para concluir o card.
