| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Cada número/claim possui fonte ou está identificado como hipótese. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell

```

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c docs/rb-074-criar-slides-e-roteiro-de-apresentacao-do-mvp
```

Se essa branch já existe, use `git switch docs/rb-074-criar-slides-e-roteiro-de-apresentacao-do-mvp` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-074.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-074.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-074.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-074.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-074: Criar slides e roteiro de apresentação do MVP"
git push -u origin docs/rb-074-criar-slides-e-roteiro-de-apresentacao-do-mvp
```

No GitHub, abra **Pull requests → New pull request**, base `main`, compare `docs/rb-074-criar-slides-e-roteiro-de-apresentacao-do-mvp`. Use o [modelo de PR](../../.github/PULL_REQUEST_TEMPLATE.md). Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head docs/rb-074-criar-slides-e-roteiro-de-apresentacao-do-mvp --web` após o push.

Preencha no PR:

## 8. Quando pedir review e quando concluir

Peça revisão e mova para **Review** quando o PR tiver escopo conferível, documentação e validação anexadas. Resolva os comentários na mesma branch e repita os checks afetados. O autor não aprova o próprio PR. **Done** exige revisão, merge e validação do resultado integrado conforme o card/DoD; abrir PR ou publicar este manual não basta.

Se houver bloqueio, registre: passo que falhou, erro sanitizado, tentativa feita, dependência e ajuda necessária. Não simule sucesso para concluir o card.
