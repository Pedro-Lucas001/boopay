## 4. Passo a passo da tarefa

1. Valide payload e merchant contra integração autenticada antes de gravar.
2. Use integração + source_id como chave do produto, com revisão monotônica e tombstone.
3. Grave recibo de event_id e mudanças do lote na mesma transação.
4. Diferencie repetição do mesmo corpo de conflito do mesmo ID com corpo diferente.
5. Teste concorrência, falha no meio do lote e snapshot sem variantes antes de registrar resultado.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Repetição preserva contagens e retorna duplicate; conflito não altera dados. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Falha no lote faz rollback; evento antigo não ressuscita produto excluído. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check
git diff --check
```

Acrescente teste comportamental pertinente em `tests/*.test.ts`, incluído pelo runner atual, quando houver código novo. Configure apenas ambientes descartáveis/autorizados para banco, loja e PSP; fixtures não comprovam integração externa.

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c feat/rb-016-implementar-ingestao-idempotente-do-catalogo
```

Se essa branch já existe, use `git switch feat/rb-016-implementar-ingestao-idempotente-do-catalogo` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-016.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-016.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-016.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-016.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-016: Implementar ingestão idempotente do catálogo"
git push -u origin feat/rb-016-implementar-ingestao-idempotente-do-catalogo
```

No GitHub, abra **Pull requests → New pull request**, base `main`, compare `feat/rb-016-implementar-ingestao-idempotente-do-catalogo`. Use o [modelo de PR](../../.github/PULL_REQUEST_TEMPLATE.md). Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head feat/rb-016-implementar-ingestao-idempotente-do-catalogo --web` após o push.
