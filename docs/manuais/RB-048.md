## 4. Passo a passo da tarefa

1. Defina referência de compra única e vínculo com sessão/tenant antes de criar pedido.
2. Use APIs WooCommerce compatíveis com HPOS para criar e consultar pedido, evitando SQL nas tabelas de pedidos.
3. Proteja concorrência no core e no ponto de integração, sem depender apenas de memória do processo.
4. Após timeout, procure a referência original antes de reenviar criação.
5. Teste concorrência e reinício em loja autorizada e registre o ID único resultante.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Duas chamadas com a mesma referência retornam o mesmo pedido. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Resposta perdida após criação é recuperada sem novo pedido, com HPOS exercitado. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check
git diff --check
```

Acrescente teste comportamental pertinente em `tests/*.test.ts`, incluído pelo runner atual, quando houver código novo. Configure apenas ambientes descartáveis/autorizados para banco, loja e PSP; fixtures não comprovam integração externa.

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c feat/rb-048-implementar-criacao-e-recuperacao-de-pedido-wooc
```

Se essa branch já existe, use `git switch feat/rb-048-implementar-criacao-e-recuperacao-de-pedido-wooc` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-048.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-048.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-048.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-048.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-048: Implementar criação e recuperação de pedido WooCommerce"
git push -u origin feat/rb-048-implementar-criacao-e-recuperacao-de-pedido-wooc
```

No GitHub, abra **Pull requests → New pull request**, base `main`, compare `feat/rb-048-implementar-criacao-e-recuperacao-de-pedido-wooc`. Use o [modelo de PR](../../.github/PULL_REQUEST_TEMPLATE.md). Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head feat/rb-048-implementar-criacao-e-recuperacao-de-pedido-wooc --web` após o push.

## 8. Quando pedir review e quando concluir

Peça revisão e mova para **Review** quando o PR tiver escopo conferível, documentação e validação anexadas. Resolva os comentários na mesma branch e repita os checks afetados. O autor não aprova o próprio PR. **Done** exige revisão, merge e validação do resultado integrado conforme o card/DoD; abrir PR ou publicar este manual não basta.

Se houver bloqueio, registre: passo que falhou, erro sanitizado, tentativa feita, dependência e ajuda necessária. Não simule sucesso para concluir o card.
