## 4. Passo a passo da tarefa

1. Confirme modo TEST, configuração permitida e PSP capaz de processar o token daquele fluxo.
2. Renderize opção Google Pay apenas quando elegível no ambiente, com alternativa de indisponibilidade.
3. Colete autorização explícita e encaminhe token somente ao backend permitido; não grave credencial em logs.
4. Relacione resultado à sessão e confirmação vigentes do core.
5. Exercite autorização, fechamento/cancelamento e falha; diferencie botão/token gerado de pagamento realmente confirmado.

Fontes técnicas para consultar na revisão escolhida: [Google Pay handler UCP: contrato específico](https://developers.google.com/pay/api/universal-commerce-protocol/google-pay-payment-handler). Reconfira versão e disponibilidade na data da implementação.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell

git pull --ff-only origin main
git switch -c feat/rb-051-implementar-google-pay-de-teste-no-checkout
```

Se essa branch já existe, use `git switch feat/rb-051-implementar-google-pay-de-teste-no-checkout` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell

    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-051.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-051.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell

Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:
