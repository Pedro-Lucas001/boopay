## 4. Passo a passo da tarefa

1. Confira emissão do código pela rota administrativa e vínculo com tenant, merchant e URL da loja.
2. Armazene hash do código, validade e consumo único; proteja consumo concorrente por transação/constraint.

4. Implemente revogação e rejeição de integrações desativadas sem vazar existência de outra loja.
5. Amplie testes de código expirado, reutilizado, loja errada e duas tentativas simultâneas.

## Implementação e evidência desta branch

Foi implementado o serviço de códigos de cinco minutos/uso único, troca transacional e revogação, persistidos no Prisma/SQLite atual. Token em SHA-256; segredo HMAC cifrado em AES-256-GCM com chave externa ao repositório. O código vincula tenant, Merchant existente e URL HTTPS normalizada.

A [entrega RB-011](../entregas/RB-011.md) contém endpoints, configuração, reprodução, limites e autorrevisão. `npm run check` passou: 3 testes, incluindo banco temporário real, expiração, uso concorrente único, vínculo, persistência e revogação. A proteção das operações de catálogo fica no PR dependente RB-013; a conexão pelo plugin e o cadastro/fixtures RB-007 ainda precisam ser integrados.
