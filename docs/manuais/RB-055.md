## 4. Passo a passo da tarefa

1. Escolha contrato/versão de cada feed e capacidade de descoberta, com mapeamento loja → produto → variante.
2. Use IDs compatíveis com o item do checkout e registre campos de disponibilidade/atualização.
3. Filtre produtos inválidos, excluídos ou inelegíveis com motivos consultáveis.
4. Valide payload e atualização incremental; não inclua segredo no perfil público.
5. Documente publicação técnica separada de aprovação do feed, Merchant Center e ativação externa.

Fontes técnicas para consultar na revisão escolhida: [Google: Merchant Center/feed e IDs](https://developers.google.com/merchant/ucp/guides/overview/merchant-center). Reconfira versão e disponibilidade na data da implementação.


## 5. Como validar

Na primeira preparação, siga o [README](../../README.md) e execute `npm ci --ignore-scripts` e `npm run db:generate` antes de comandos que usem dependências. Node 22 e PHP 8.3 são as versões de referência do CI. Variáveis e segredos são locais; consulte `.env.example` e o guia do componente.

| Caso mínimo | Ação e resultado a verificar | Registro |
| --- | --- | --- |
| V1 | Variante no feed referencia o mesmo item comprado no checkout. | Não executado por este manual; registrar resultado e link na entrega. |
| V2 | Produto excluído deixa de ser distribuído e feed local não é rotulado como aprovado no Google. | Não executado por este manual; registrar resultado e link na entrega. |

Execute na raiz, após produzir sua alteração:

```powershell
npm run check
git diff --check
```

Acrescente teste comportamental pertinente em `tests/*.test.ts`, incluído pelo runner atual, quando houver código novo. Configure apenas ambientes descartáveis/autorizados para banco, loja e PSP; fixtures não comprovam integração externa.

Para cada critério abaixo, preencha na entrega: preparação, ação, esperado, observado, passou/falhou/não executado e evidência. Para design/documentação, inclua revisão de leitura/links/protótipo; não crie teste de código artificial. Uma execução antiga não comprova seu commit atual.

## 7. Branch, documentação e PR pelo terminal

Se é seu primeiro trabalho, clone e configure autoria conforme o [tutorial](../../README.md). Dentro de `boopay`, com trabalho anterior salvo na branch correta e árvore limpa:

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c feat/rb-055-implementar-feeds-e-descoberta-do-catalogo-agent
```

Se essa branch já existe, use `git switch feat/rb-055-implementar-feeds-e-descoberta-do-catalogo-agent` para continuar; não execute `-c` novamente. Prepare seu documento sem sobrescrever uma entrega existente:

```powershell
if (-not (Test-Path 'docs/entregas/RB-055.md')) {
    Copy-Item 'docs/entregas/MODELO.md' 'docs/entregas/RB-055.md'
}
```

Faça os passos da seção 4 e preencha `docs/entregas/RB-055.md`: autor, issue, manual, objetivo, arquivos, decisões, preparação, passos, esperado/observado, evidências e pendências. Remova os campos de orientação do modelo e preserve versões anteriores. Para artefato externo, versione o roteiro/registro com link acessível, exportação ou capturas pertinentes; não abra PR vazio.

Antes de enviar, execute a seção 5 e confira seleção de arquivos:

```powershell
git diff --stat
git diff
git status --short
git add -- docs/entregas/RB-055.md
```

O comando acima seleciona apenas a documentação. Selecione também cada arquivo de código/teste/artefato que você criou ou alterou com `git add -- caminho/do/arquivo` (substitua pelo caminho real). Confira `git status --short` e não inclua `.env`, banco local, credenciais ou trabalho de outra tarefa. Depois:

```powershell
git diff --cached --check
git diff --cached
git commit -m "RB-055: Implementar feeds e descoberta do catálogo agêntico"
git push -u origin feat/rb-055-implementar-feeds-e-descoberta-do-catalogo-agent
```

No GitHub, abra **Pull requests → New pull request**, base `main`, compare `feat/rb-055-implementar-feeds-e-descoberta-do-catalogo-agent`. Use o [modelo de PR](../../.github/PULL_REQUEST_TEMPLATE.md). Quem já tem GitHub CLI autenticado pode usar `gh pr create --base main --head feat/rb-055-implementar-feeds-e-descoberta-do-catalogo-agent --web` após o push.

## 8. Quando pedir review e quando concluir

Peça revisão e mova para **Review** quando o PR tiver escopo conferível, documentação e validação anexadas. Resolva os comentários na mesma branch e repita os checks afetados. O autor não aprova o próprio PR. **Done** exige revisão, merge e validação do resultado integrado conforme o card/DoD; abrir PR ou publicar este manual não basta.

Se houver bloqueio, registre: passo que falhou, erro sanitizado, tentativa feita, dependência e ajuda necessária. Não simule sucesso para concluir o card.
