## Mudança

CONTRIBUTING, modelo de PR, modelo de entrega e workflow validate. Comandos de
TypeScript, JavaScript, PHP, links da documentação e testes de contrato.
Extração do schema de catálogo sem mudar seu comportamento. Configuração
Node16 substitui a resolução node10 rejeitada pelo TypeScript 6.

## Evidências locais — 2026-10-10

Ambiente: Windows, Node 24.18.0, Prisma Client 5.22.0.

| Comando | Resultado observado |
| --- | --- |
| npm ci --ignore-scripts --no-audit --no-fund | 62 pacotes instalados |
| npm run db:generate | Cliente Prisma gerado |
| npm run build | Sucesso após corrigir TS5107 |
| npm run check:js | 3 arquivos válidos |
| npm run check:php | Nenhum PHP presente nesta branch; não é teste do plugin |
| npm run check:docs | 89 arquivos, links relativos válidos |
| npm test | 2 testes, 2 passaram, 0 falhas |

No Windows, a restrição do ambiente impediu inicialmente tsx de executar
os testes (uv_os_get_passwd). A execução autorizada fora dessa restrição passou.
O workflow usa Linux/Node 22; resultado remoto deve ser conferido no PR.

## Autorrevisão

- A extração do schema mantém os campos existentes.
- Os testes rejeitam operação desconhecida e ausência de merchant_id.
- A rota existente ainda não autentica pedidos: tratado em RB-011/RB-013.
- A proteção da main não foi alterada nem validada.
- A pasta de banco já versionada não é removida nesta entrega; a regra
  de ignore impede novos bancos locais, mas não apaga arquivos rastreados.

## Pendências para aceite integral

Todos os integrantes demonstrarem clone/branch/PR e o proprietário
confirmar proteção da main. Testes de contrato não comprovam instalação
do plugin nem os critérios de HPOS.
