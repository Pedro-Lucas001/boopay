# RB-081 — Base operacional multiloja

Autor: Thiago Ventura, apoio de Codex. Issue [#19](https://github.com/Pedro-Lucas001/boopay/issues/19). Checkpoint do autor: segunda, 19/10/2026. Revisão independente pendente.

[Contrato, APIs e reprodução](../contratos/multiloja.md). Entrega: vínculo imutável merchant/tenant, credenciais de operador separadas, papéis reader/writer, seleção autorizada, consultas de catálogo/saúde, conexão/revogação por loja, migration de legado e console mínimo desktop/mobile.

## Decisões e desafios

- A base anterior permitia associar um merchant a tenants diferentes. A nova validação fixa o dono e rejeita emissão/troca/autenticação incompatíveis.
- SKU legado tinha unicidade global; agora é composto com merchant. Identidade de catálogo/eventos continua por integração.
- Migration não inventa propriedade de legado ambíguo: bloqueia para revisão.
- Revogação é lida no servidor a cada request. Não há cache compartilhado de contexto.
- O teste anterior de ingestão usava um merchant para dois tenants; foi corrigido para duas lojas distintas, mantendo os cenários negativos e de repetição.
- No Windows, o helper de migration precisou criar o arquivo SQLite vazio antes de chamar Prisma, como os testes existentes. Nenhum banco compartilhado foi alterado.

## Validação

`npm run check` passou: 8 testes Node, 6 grupos PHP, compilação, JS e links. Testes usam bancos temporários novos e upgrade a partir da cadeia anterior de migrations. [Evidências e capturas](../evidencias/RB-081/README.md). UI: duas lojas mostram preços distintos para o mesmo ID; conta restrita só lista sua loja; desktop/mobile e logout conferidos.

## Limites e aceite

É a base S1 sobre SQLite. PostgreSQL, Firestore/BigQuery, CDP, core e pedidos futuros ainda exigem integração e regressão multiloja; não foram implementados por esta entrega. Console funcional não substitui o frontend completo do time. `Refs #19`: não fechar a issue antes de cumprir o aceite integrado de todas as fronteiras. Esta entrega não antecipa as tarefas dos outros integrantes nem muda seus responsáveis.
