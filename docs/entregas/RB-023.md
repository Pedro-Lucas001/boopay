# RB-023 — Arquitetura e decisões da S1

Autor: Thiago Ventura, apoio de Codex. Issue [#7](https://github.com/Pedro-Lucas001/boopay/issues/7). Revisão solicitada a Pedro Lucas; independente pendente. Checkpoint do autor: segunda, 19/10/2026.

## Entrega e decisões

[Arquitetura](../arquitetura.md) com componentes existentes/futuros, fontes de verdade, interfaces, divisão plugin/API/dados/IA/frontend e estratégia de falhas. Escolhas centrais: core único, confirmação versionada, isolamento por contexto autorizado, idempotência persistente, projeções reconstruíveis e migração SQLite → PostgreSQL em tarefa própria.

## Como conferir

1. Compare a tabela de interfaces existentes com `src/http/connection-routes.ts` e `src/http/routes.ts`.
2. Compare o datasource com `prisma/schema.prisma`: SQLite está descrito como atual e PostgreSQL como alvo.
3. Percorra o fluxo de compra e localize autoridade de cotação, confirmação, pagamento e pedido.
4. Confira que cada componente futuro tem tarefa/interface e que erros incertos não autorizam repetição cega.
5. Execute `npm run check:docs` e `git diff --check`.
